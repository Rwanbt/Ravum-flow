## The `--bins` scope mismatch (why `commands*` looks weak)

The workflow runs `cargo test -- --bins`, i.e. **only the unit tests inside the binary**. The command
bodies and policy helpers are mainly exercised by the *integration* suites (`tests/cli.rs`,
`tests/proposals.rs`, `tests/concurrency.rs`), which `--bins` excludes. A low `commands*` rate
therefore means "the unit suite alone does not pin this logic", not "the logic is untested" — the
integration suite is exactly what the mutation is trying to break, and it is not consulted here. This
is a **scope limitation of the harness**, not a result to optimise by deleting the module split.

Follow-up before any threshold: run the `commands*` modules with the integration suites (for example
`-- --test cli --test proposals --test concurrency`), or accept that their unit-scope rate stays low and
gate only the modules whose tests live in the binary. The campaign does not claim a crate-wide score.

## Two harness defects found by this campaign

1. **A moved file silently measured nothing.** After `commands.rs` became `commands/mod.rs`, the matrix
   still asked for `crates/flow/src/commands.rs`; `cargo-mutants` accepted the nonexistent path, found
   zero mutants and exited 0, so the job reported **success** with a 0-mutant result. The workflow now
   maps `commands` → `commands/mod.rs`, adds `commands-policy` and `commands-checkout`, and the summary
   **fails** when a module produces zero mutants instead of printing a 0 % score.
2. **Timeouts were treated as a broken campaign.** `cargo-mutants` exits **3** when some mutants time
   out; the step only tolerated 0 (all caught) and 2 (survivors), so `lock` failed although it had
   produced a complete report. Exit 3 is now accepted in report mode with an explicit warning, and
   timeouts are counted in the denominator, never as killed.

## What the survivors mean

The missed mutants concentrate in **refusal and comparison branches** (`assemble`'s re-derivation
comparisons, `lock`'s io-error match guards, journal/segment error paths). That is consistent with the
coverage gap the wave closed line-by-line but did not pin assertion-by-assertion: a test can execute a
refusal branch without distinguishing the exact comparison that produced it. This campaign is the
evidence for the next test wave, not a pass.

No threshold is enforced yet: the workflow stays report mode until a baseline is agreed. The three
`commands*` modules were measured with the fixed mapping in the re-dispatched run; their low rates are
explained by the `--bins` scope above.
