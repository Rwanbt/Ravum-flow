Measured on 2026-11-10 (Europe/Paris) on Windows 11, Rust nightly + rustc 1.95.0,
`cargo-llvm-cov 0.9.1`, on the working tree whose only uncommitted files were
agent artefacts (no `crates/flow/src` or `crates/flow/tests` change).

## Exact commands (a clean profile state is mandatory)

```bash
CARGO_TARGET_DIR=D:\App\Ravum-flow\wt-quality-target CARGO_BUILD_JOBS=4
cargo +nightly llvm-cov clean --workspace
cargo +nightly llvm-cov --locked --offline --all-targets --branch \
  --ignore-filename-regex '[\\/]tests[\\/]' --no-report
cargo +nightly llvm-cov report --branch --ignore-filename-regex '[\\/]tests[\\/]'
```

The final code adds the checkout re-check and containment paths (≈120 source
lines); the new gates exercise them, so the global percentage holds. The
candidate gates (90 % lines / 85 % branches) are **not met**; the honest reasons
and the exact uncovered regions are in `docs/reviews/FLOW-QUALITY-WAVE3.md`
(§3.1): most of `scratch.rs`'s uncovered lines are only reachable by importing
the module directly, which the prescribed `tests/` filter discards, and the
remaining ones need injected filesystem failures.

## Caveats (measured)

- profraw files accumulate in the target directory: without the `clean` step an
  identical tree drifted by 9 lines / 2 branch points. Two cleaned identical
  runs still varied by ±1 branch point.
- `--ignore-filename-regex '[\\/]tests[\\/]'` also discards coverage of source
  modules imported by integration tests through `#[path = "../src/x.rs"]`; that
  is why `scratch.rs` cannot honestly reach 85 % under this command.
