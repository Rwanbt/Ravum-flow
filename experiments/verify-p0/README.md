# experiments/verify-p0 — independent review of the P0 checkout-fidelity fix

Disposable-fixture attack harness used by
[`docs/reviews/FLOW-P0-GIT-FIDELITY-REVIEW.md`](../../docs/reviews/FLOW-P0-GIT-FIDELITY-REVIEW.md).
Nothing here is product code; do not import it.

## Contents

| File | Purpose |
|---|---|
| `p0_attacks.py` | 19 adversarial scenarios. Runs the **post-fix** binary and, on the same fixture, a **pre-fix** binary, so "pre `PASSED` → post `REFUSED`" is measured, not claimed. |
| `smudge.rs` / `smudge.exe` | Same-length smudge filter (ASCII upper-caser) used as `filter.<driver>.smudge`. |
| `passthru.rs` / `passthru.exe` | Pass-through `filter.<driver>.clean`, so Git's index refresh does not fail before the checkout gate is reached. |
| `linux_probe.sh` | WSL/Linux data point: local-filter refusal + TOCTOU reproduction; builds the pinned binary itself. |
| `results-p0.json` | Machine-readable result of the canonical run (post-fix binary `5077c50`, pre-fix binary `0de8c21`). |
| `p0-run.log` | Console output of that run. |
| `verdict-tables-wave3.md` | Per-axis tables generated by `experiments/mvp-qa/attacks.py` for the wave-3 campaign. |
| `campaign-wave3.log` / `campaign-119.log` | Console logs of the wave-3 campaign (122 scenarios on 5077c50) and the literal 119 replay (dfb941d). |
| `summarize_wave3.py` | Re-derives the campaign numbers in the wave-3 review from `results-wave3.json` and the wave-2 `results.json`. |

## Rebuild the helpers (Rust 1.95.0, no dependencies)

```powershell
rustc -O experiments/verify-p0/smudge.rs  -o experiments/verify-p0/smudge.exe
rustc -O experiments/verify-p0/passthru.rs -o experiments/verify-p0/passthru.exe
```

## Run

```powershell
# post-fix binary from `git archive <sha>` (never the shared worktree)
python experiments/verify-p0/p0_attacks.py `
  --post  <postfix-debug-flow.exe> `
  --pre   <prefix-0de8c21-debug-flow.exe> `
  --out   experiments/verify-p0/results-p0.json
```

`--only A07,A08` runs a subset; `FLOW_P0_KEEP=1` keeps the fixtures. `--filter` is not used here;
scenario ids are `A01`…`A19`.

The scenario ids and the expected/observed columns are listed in §3 of the review. Fixtures are
created under `%TEMP%` and removed on exit; no network, no credentials, no real project.

## Notes on Windows fixtures

- `Path.write_text` translates `"\n"` to CRLF on Windows. Fixtures that need an LF blob for an
  `eol=crlf` conversion write bytes (`write_bytes` / `write_file(..., bytes)`), otherwise the
  conversion is a no-op and the scenario silently stops testing the gate.
- `git write-tree`/`status` refresh the index. A required `filter.<driver>` with only a `smudge`
  command fails during that refresh, *before* the checkout; configure a pass-through `clean` too.
- The TOCTOU scenario needs a background writer detached from the hook (`( sleep N; … ) &` with
  stdout/stderr redirected), otherwise Git waits for it and the rewrite lands before the check.
